Topic 5.1

Introduction to Securities in Operating System and Network

Operating System Security refers to the measures and controls implemented to protect the operating system from threats, vulnerabilities, and unauthorized access. Network Security refers to the measures taken to protect the confidentiality, integrity, and availability of data as it travels across network connections. Both are essential for overall information security.
📌 Last Night Tip
Remember that operating system security and network security work together. The operating system protects the computer from local threats. Network security protects data as it travels between computers. If either one fails, the entire system is vulnerable. Think of it like a house with a strong front door (operating system security) but open windows (network security).

What is Operating System Security?

An operating system is the most important software on a computer. It manages hardware, runs applications, and controls access to files and resources. Operating system security is the set of controls that protect the operating system from threats.

The main goals of operating system security are:

  • Prevent unauthorized users from accessing the system.
  • Prevent authorized users from accessing data they are not supposed to see.
  • Protect system files and configuration from modification.
  • Ensure the system continues to function correctly even during attacks.
  • Provide audit logs to track who did what and when.
Real World Example — Operating System Security in Action

Example: Windows Login Screen When you turn on a Windows computer, the first thing you see is a login screen. You must enter a username and password. This is operating system security. The operating system is checking your identity before allowing you to use the computer. Without this protection, anyone who walked up to your computer could access all your files, emails, and saved passwords.

Key Components of Operating System Security

🔑

Authentication

Authentication is the process of verifying that a user is who they claim to be. The most common authentication method is a username and password. More secure methods include biometrics (fingerprint, face recognition), smart cards, and security tokens. Strong authentication is the first line of defense for any operating system.

🛡️

Authorization and Access Control

After a user is authenticated, the operating system must decide what that user is allowed to do. This is called authorization. Operating systems use access control lists and permissions to control access to files, folders, and system settings. For example, a regular user can read their own files but cannot install software or change system settings. An administrator can do everything.

📋

Audit and Logging

Operating systems record events in log files. These logs include successful logins, failed login attempts, file access, system changes, and errors. Audit logs are essential for detecting security incidents, investigating what happened, and meeting compliance requirements.

🔒

Memory Protection

Modern operating systems prevent one program from accessing the memory of another program. This is called memory protection. Without memory protection, a malicious program could read passwords, credit card numbers, or other sensitive information from other programs. Memory protection also prevents programs from crashing the operating system.

👤

User Account Control

User Account Control (UAC) is a feature in Windows that prompts for permission before making system changes. Even if you are logged in as an administrator, User Account Control asks for confirmation before installing software or changing system settings. This prevents malware from making changes without your knowledge.

🔄

Patch Management

Operating system vendors regularly release updates called patches. Patches fix security vulnerabilities, add features, and improve performance. Keeping the operating system updated with the latest patches is one of the most important security practices. Unpatched operating systems are a primary target for attackers.

What is Network Security?

Network security is the practice of protecting computer networks from intruders, attacks, and data interception. While operating system security protects a single computer, network security protects the communication between computers.

The main goals of network security are:

  • Prevent unauthorized access to the network.
  • Prevent attackers from intercepting or modifying data as it travels across the network.
  • Ensure that network resources (servers, printers, internet connection) are available to authorized users.
  • Detect and block malicious network traffic.

Key Components of Network Security

🔥

Firewalls

A firewall is a device or software that controls what traffic is allowed to enter and leave a network. Firewalls examine network packets and block or allow them based on rules. For example, a firewall might allow web traffic (port 80 and 443) but block file sharing traffic (port 445) from the internet.

🔐

Encryption

Encryption scrambles data so that it cannot be read by anyone who intercepts it. Network encryption protocols such as Transport Layer Security (TLS) and Internet Protocol Security (IPsec) protect data as it travels across the network. When you see "https" in your browser address bar, your connection to that website is encrypted.

📡

Intrusion Detection and Prevention

Intrusion Detection Systems (IDS) monitor network traffic for suspicious patterns and alert administrators. Intrusion Prevention Systems (IPS) can also block malicious traffic automatically. These systems help detect attacks such as port scans, denial of service attempts, and exploit attempts.

🚪

Network Access Control

Network Access Control (NAC) ensures that only authorized and compliant devices can connect to the network. Before a device is allowed to connect, Network Access Control checks whether it has up to date antivirus software, installed patches, and proper configuration. Devices that do not meet the requirements are placed in a quarantine network until they are fixed.

🌐

Virtual Private Network (VPN)

A Virtual Private Network (VPN) creates an encrypted tunnel between your device and a remote network. This protects your data from interception when using public Wi-Fi or accessing the internet from untrusted locations. VPNs are commonly used by employees to securely connect to their office network from home.

✂️

Network Segmentation

Network segmentation divides a large network into smaller, isolated segments. If an attacker compromises one segment, they cannot easily reach other segments. For example, a company might put its customer database in a separate network segment that is not accessible from the general office network.

Real World Example — Network Security in a Bank

Example: How a Bank Protects Its Network A bank uses multiple layers of network security.

  • Perimeter Firewall: Blocks unauthorized traffic from the internet.
  • Internal Firewall: Separates the customer database network from the employee network.
  • Encryption: All customer data is encrypted before being transmitted over the network.
  • Intrusion Prevention System: Monitors traffic for attack patterns and blocks them automatically.
  • Virtual Private Network (VPN): Employees use a Virtual Private Network to connect to the bank's network from home, ensuring that all communication is encrypted.
  • Network Access Control: Before an employee's laptop is allowed on the network, it is checked for up to date antivirus and patches.
  • Network Segmentation: The automatic teller machine network is completely separate from the employee network.

Common Operating System Vulnerabilities

Known Vulnerabilities

  • Unpatched software vulnerabilities (missing security updates)
  • Weak password policies (users choosing "password123")
  • Default accounts that were never disabled
  • Unnecessary services running (each service is a potential entry point)
  • Misconfigured permissions (users having too much access)

Zero Day Vulnerabilities

  • Vulnerabilities that are not yet known to the operating system vendor
  • No patch is available because the vendor does not know about the vulnerability
  • Attackers can exploit zero day vulnerabilities before anyone can protect against them
  • Zero day attacks are rare but very dangerous

Common Network Vulnerabilities

📡

Unencrypted Communication

Sending data without encryption allows attackers to intercept and read it. This is especially dangerous on public Wi-Fi networks where many people can see the traffic.

🔓

Open Ports and Services

Every open network port is a potential entry point for attackers. Unnecessary open ports increase the attack surface. Attackers scan for open ports to find vulnerable services.

🔑

Weak Network Authentication

Wi-Fi networks using old security protocols (Wired Equivalent Privacy or WEP, Wi-Fi Protected Access or WPA) can be easily cracked. Weak passwords on network devices allow attackers to gain access.

⚠️ Important Note — Defense in Depth

No single security control is perfect. Defense in depth means using multiple layers of security so that if one layer fails, other layers still protect the system. For example, an organization might use firewalls, intrusion detection systems, antivirus software, strong passwords, encryption, and employee training. Each layer provides additional protection. Relying on only one security measure (such as a firewall) is dangerous because that one measure could fail or be bypassed.

Key Takeaways for Topic 5.1

Operating system security protects individual computers through authentication, authorization, auditing, memory protection, user account control, and patch management. Network security protects communication between computers through firewalls, encryption, intrusion detection, network access control, virtual private networks, and network segmentation. Both operating system security and network security are essential for overall information security. They work together as layers in a defense in depth strategy. Weakness in either area can lead to a security breach.

Topic 5.2

Rootkit and Anti Rootkit Tools (Antivirus Based)

A rootkit is a malicious software that hides its presence and the presence of other malware on an infected computer. Rootkits are designed to avoid detection by operating systems and security software. Anti rootkit tools are specialized security tools designed to detect and remove rootkits.
📌 Last Night Tip
Remember the word "rootkit" comes from "root" (the administrator account on Unix and Linux systems) and "kit" (a collection of tools). A rootkit gives attackers administrator level access while hiding their presence. Traditional antivirus software often cannot detect rootkits because rootkits hide from the operating system.

What is a Rootkit?

A rootkit is a collection of malicious software tools that gives an attacker unauthorized access to a computer while hiding the attacker's presence. The name "rootkit" comes from two words:

  • Root: The most powerful user account on Unix and Linux systems (similar to Administrator on Windows).
  • Kit: A collection of tools and software.

Rootkits are dangerous because they are designed to be invisible. They hide their files, processes, network connections, and registry entries from the operating system and from security software.

Real World Example — How a Rootkit Works

Example: A Rootkit Hiding Itself Imagine you have a security camera in your office. A thief enters the office. If the thief steals the camera, you will know something happened because the camera is missing. That is like normal malware. Now imagine a thief who hacks into the camera's software. The camera continues to show an empty room even though the thief is there. That is a rootkit. The rootkit hides the attacker's presence by intercepting and changing what the operating system and security software see.

How Rootkits Work

Rootkits work by modifying the operating system or intercepting system calls. A system call is a request that a program makes to the operating system to perform an action, such as opening a file or listing running processes.

When a rootkit is installed, it does the following:

  • Modifies System Calls: The rootkit intercepts system calls that ask for information about running processes, files, or network connections. It returns fake information that does not include the rootkit itself.
  • Hides Files: When the operating system asks for a list of files in a directory, the rootkit removes its own files from the list before returning it.
  • Hides Processes: When a security tool asks for a list of running processes, the rootkit removes its own processes from the list.
  • Hides Network Connections: When the system asks for a list of active network connections, the rootkit removes connections used by the rootkit.
  • Maintains Persistence: The rootkit ensures that it starts every time the computer boots up.
Fig 5.1 — How a Rootkit Hides from the Operating System
Security Tool asks: "What processes are running?"
↓
Operating System asks the kernel for process list
↓
Rootkit intercepts the request and modifies the list
↓
Rootkit removes its own process from the list
↓
Security Tool receives the modified list (without the rootkit)
↓
Security Tool thinks everything is normal (but the rootkit is running)

Types of Rootkits

💿

User Mode Rootkits

User mode rootkits operate at the application level. They intercept system calls by modifying application programming interface (API) functions or replacing system libraries. User mode rootkits are easier to detect than kernel mode rootkits because security tools can also operate at the user level. They are less dangerous than kernel mode rootkits but still very harmful.

⚙️

Kernel Mode Rootkits

Kernel mode rootkits operate at the core of the operating system (the kernel). The kernel has complete control over the computer. Kernel mode rootkits are extremely dangerous and difficult to detect because they run at the same privilege level as the operating system itself. They can intercept and modify any system call, hide any information, and control everything on the computer.

📀

Bootkit (Boot Sector Rootkit)

A bootkit infects the master boot record or the boot loader. It loads before the operating system starts. This means the rootkit is active from the moment the computer is turned on. Bootkits are very difficult to detect because they load before any security software. They can survive operating system reinstallation.

🧠

Firmware Rootkit

A firmware rootkit infects the firmware of a hardware device such as the computer's Basic Input Output System (BIOS) or Unified Extensible Firmware Interface (UEFI), a network card, or a hard drive controller. Firmware rootkits are extremely rare but very sophisticated. They can survive operating system reinstallation and even hard drive replacement.

📱

Virtual Rootkit

A virtual rootkit installs a virtual machine monitor (hypervisor) below the operating system. The rootkit then runs the original operating system inside a virtual machine. The rootkit can observe and control everything the operating system does without the operating system knowing. This is called a hypervisor rootkit or virtual rootkit.

How Rootkits Get Installed

Rootkits do not install themselves. They are delivered by other malware or installed by attackers who have already gained access to the computer. Common delivery methods include:

  • Trojan Horses: A rootkit is hidden inside seemingly legitimate software. When the user installs the software, the rootkit is also installed.
  • Exploits: Attackers exploit a vulnerability in the operating system or an application to install the rootkit remotely.
  • Drive by Downloads: A user visits a malicious website, and the website automatically downloads and installs the rootkit without the user's knowledge.
  • Physical Access: An attacker with physical access to the computer can install a rootkit directly, such as by booting from a USB drive.
  • Other Malware: A virus or worm may download and install a rootkit after infecting the computer.

Signs of a Rootkit Infection

Rootkits are designed to be invisible, but there may still be signs of infection.

  • The computer becomes slow or behaves strangely.
  • Antivirus software stops working or cannot be updated.
  • Security software cannot be installed or runs but finds nothing even though you know there is a problem.
  • Task Manager shows high central processing unit (CPU) usage but no obvious processes are using the CPU.
  • Network activity is high even when no programs are using the network.
  • System settings change by themselves.
  • New user accounts appear that you did not create.
⚠️ Important Note — Rootkits are Hard to Detect

Traditional antivirus software often cannot detect rootkits. Antivirus software relies on the operating system to provide information about files, processes, and registry entries. Because rootkits modify what the operating system reports, antivirus software cannot see the rootkit. This is why rootkits are so dangerous. Specialized anti rootkit tools are needed to detect and remove them.

Anti Rootkit Tools

Anti rootkit tools are specialized security tools designed to detect and remove rootkits. They use different techniques than traditional antivirus software to find hidden malware.

Common Anti Rootkit Tools

  • Malwarebytes Anti-Rootkit: A free tool that scans for and removes rootkits. It is one of the most popular anti rootkit tools.
  • Kaspersky TDSSKiller: A free tool specifically designed to remove the TDSS rootkit and similar threats.
  • Sophos Virus Removal Tool: Includes anti rootkit scanning capabilities.
  • Bitdefender Rootkit Remover: A standalone tool for detecting and removing rootkits.
  • McAfee Rootkit Remover: A command line tool that scans for and removes rootkits.
  • GMER: An advanced tool for detecting rootkits by comparing low level system information with what the operating system reports.

How Anti Rootkit Tools Detect Rootkits

  • Cross View Detection: The tool reads system information directly from the kernel or from raw disk access, bypassing the operating system's application programming interface (API). Then it compares this low level information with what the operating system reports. If there are differences, a rootkit is likely present.
  • Integrity Checking: The tool checks the integrity of system files, system call tables, and kernel data structures. Rootkits often modify these to hide themselves. The tool compares the current state with known good values.
  • Behavioral Analysis: The tool monitors system behavior for suspicious patterns that might indicate a rootkit, such as hidden processes or unusual system call patterns.
  • Memory Scanning: The tool scans system memory for known rootkit signatures, bypassing the rootkit's attempts to hide from the operating system.
Example — Using Malwarebytes Anti-Rootkit

Step by Step Process:

  1. Download Malwarebytes Anti-Rootkit from the official website.
  2. Run the tool as an administrator.
  3. The tool scans the system for rootkits. It may take thirty minutes to several hours depending on the size of the hard drive.
  4. If a rootkit is found, the tool displays the results.
  5. The user clicks "Clean" to remove the rootkit.
  6. The computer may need to restart to complete removal.
  7. After restarting, the tool runs again to verify the rootkit is gone.

Important Note: Some rootkits are so deep that they cannot be removed without reinstalling the operating system. In severe cases, the only way to be sure the rootkit is gone is to wipe the hard drive completely and reinstall everything from scratch.

How Antivirus Software Detects Rootkits

Modern antivirus software includes anti rootkit capabilities. They use several techniques:

  • Signature Based Detection: Antivirus software maintains a database of known rootkit signatures. When a file matches a signature, it is flagged as malware. This does not work for new or modified rootkits.
  • Heuristic Detection: Antivirus software analyzes the behavior of programs. If a program tries to hide files or processes, it may be flagged as a potential rootkit.
  • Cloud Based Detection: Antivirus software sends suspicious files to the vendor's cloud for analysis. The cloud uses many different detection engines to identify rootkits.
  • Boot Time Scanning: Some antivirus software can scan the system before the operating system loads. Since rootkits are not active yet, they cannot hide from the scan.
⚠️ What to Do If You Find a Rootkit
  • Disconnect the computer from the network immediately to prevent the attacker from accessing your data or spreading to other computers.
  • Run a trusted anti rootkit tool (download from a clean computer and transfer using a USB drive, not from the infected computer).
  • Change all passwords (email, banking, social media) from a different, clean computer.
  • Consider wiping the hard drive completely and reinstalling the operating system. This is the only way to be 100 percent sure the rootkit is gone.
  • Restore data from backups created before the infection.
Key Takeaways for Topic 5.2

A rootkit is malicious software that hides its presence on an infected computer. Rootkits intercept system calls and modify what the operating system reports. Types of rootkits include user mode rootkits, kernel mode rootkits, bootkits, firmware rootkits, and virtual rootkits. Rootkits are difficult to detect because they hide from the operating system. Anti rootkit tools use cross view detection, integrity checking, and memory scanning to find rootkits. Modern antivirus software includes anti rootkit capabilities. In severe cases, the only way to remove a rootkit is to wipe the hard drive and reinstall the operating system.

Topic 5.3

Threats to Network Communication

Threats to network communication are attacks that target data as it travels across computer networks. These threats can intercept, modify, disrupt, or block network traffic. Understanding these threats is essential for designing secure networks and protecting sensitive information.
📌 Last Night Tip
Remember the four main categories of network threats: Interception (eavesdropping), Interruption (denial of service), Modification (tampering with data), and Fabrication (creating fake data). These are sometimes called the "four I's" of network security.

Categories of Network Threats

Network threats can be classified into four main categories.

👂

Interception (Eavesdropping)

Interception occurs when an unauthorized party gains access to data as it travels across the network. The attacker listens to network traffic without modifying it. This is a threat to confidentiality.

Examples: Packet sniffing, wiretapping, man in the middle attacks

⛔

Interruption (Denial of Service)

Interruption occurs when network services become unavailable to authorized users. The attacker blocks, delays, or disrupts network communication. This is a threat to availability.

Examples: DDoS attacks, network jamming, routing attacks

✏️

Modification (Tampering)

Modification occurs when an attacker changes data while it is being transmitted. The attacker intercepts the data, modifies it, and then sends it to the destination. This is a threat to integrity.

Examples: Man in the middle modification, data alteration, session hijacking

🎭

Fabrication (Impersonation)

Fabrication occurs when an attacker creates fake network traffic or impersonates a legitimate user or system. The attacker may send false data, replay captured data, or pretend to be someone else. This is a threat to authentication and integrity.

Examples: Spoofing, replay attacks, session hijacking, man in the middle attacks

Detailed Network Threats

Packet Sniffing

Packet sniffing is the practice of capturing network traffic to analyze it. Network administrators use packet sniffers legitimately to troubleshoot network problems. Attackers use packet sniffers to steal unencrypted data such as passwords, emails, and files.

How it works: The attacker places a network interface in "promiscuous mode," which allows it to capture all traffic on the network segment, not just traffic addressed to that computer.

Protection: Encryption makes sniffed data unreadable. Using switched networks instead of hubs reduces exposure. Virtual Private Networks (VPNs) encrypt all traffic.

Man in the Middle Attack (MITM)

In a man in the middle attack, the attacker secretly positions themselves between two communicating parties. The attacker can intercept, read, modify, and forward messages. Both parties believe they are communicating directly with each other, but the attacker is relaying the messages.

How it works: The attacker intercepts the initial connection establishment and tricks both parties into connecting to the attacker instead of to each other.

Protection: Mutual authentication using certificates, using encrypted connections (HTTPS, TLS), and avoiding public Wi-Fi for sensitive transactions.

Spoofing Attacks

Spoofing is when an attacker pretends to be someone or something else. There are several types of spoofing.

  • Internet Protocol (IP) Spoofing: The attacker sends packets with a fake source IP address to hide their identity or impersonate a trusted system.
  • Address Resolution Protocol (ARP) Spoofing: The attacker sends fake ARP messages to associate their media access control (MAC) address with a legitimate IP address, allowing them to intercept traffic.
  • Domain Name System (DNS) Spoofing: The attacker poisons the DNS cache so that a domain name resolves to the attacker's IP address instead of the legitimate one.
  • Email Spoofing: The attacker sends emails with a fake sender address, making it appear that the email came from someone else.

Protection: Packet filtering, ARP inspection, DNS security extensions (DNSSEC), email authentication (SPF, DKIM, DMARC).

Replay Attack

In a replay attack, the attacker captures valid network traffic and then retransmits it later to trick the system. For example, an attacker might capture a valid login message and then replay it to log in without knowing the password.

How it works: The attacker captures network packets using a packet sniffer. Then they retransmit those packets later. If the system does not have protection against replay attacks, it will accept the replayed messages as valid.

Protection: Use timestamps and sequence numbers in messages. Use one time passwords or challenge response authentication. Use session tokens that expire quickly.

Session Hijacking

Session hijacking is when an attacker takes over a user's active session after the user has already authenticated. The attacker steals the session cookie or token and uses it to impersonate the user without needing the password.

How it works: After a user logs into a website, the website gives the user's browser a session token. If the attacker can steal this token (through packet sniffing, cross site scripting, or other methods), they can present that token to the website and be logged in as the user.

Protection: Use HTTPS for all traffic to prevent token theft. Use short session timeouts. Bind sessions to specific IP addresses. Regenerate session tokens after login.

Denial of Service (DoS) and Distributed Denial of Service (DDoS)

Denial of Service attacks overwhelm a network, server, or application with traffic, making it unavailable to legitimate users. Distributed Denial of Service attacks use many computers (a botnet) to launch the attack simultaneously from many sources.

How it works: The attacker sends more traffic than the target can handle. The target's resources (bandwidth, central processing unit, memory, or connection table) become exhausted. Legitimate requests cannot be processed.

Protection: DDoS protection services (Cloudflare, Akamai, AWS Shield), rate limiting, load balancers, network capacity planning.

Port Scanning

Port scanning is not an attack itself, but it is a reconnaissance technique used by attackers to find vulnerable services. The attacker sends packets to different ports on a target system to see which ports are open and what services are running.

How it works: The attacker uses tools like Nmap to send connection attempts to thousands of ports. Open ports indicate that a service is listening. The attacker then researches known vulnerabilities for those services.

Protection: Close unnecessary ports using a firewall. Use port knocking or port hiding techniques. Monitor for port scans using intrusion detection systems.

Routing Attacks

Routing attacks manipulate the routing protocols that direct traffic across the internet or within a network. Attackers can redirect traffic to their own systems or cause network outages.

Types: Border Gateway Protocol (BGP) hijacking (redirecting internet traffic), routing table poisoning, route flapping.

Protection: Use route filtering and authentication for routing protocols. Monitor for unexpected routing changes.

Real World Example — Man in the Middle Attack on Public Wi-Fi

Example: The Evil Twin Attack An attacker sets up a fake Wi-Fi network with a name similar to a legitimate network, such as "Starbucks_WiFi_Free" instead of the real "Starbucks WiFi." A customer connects to the fake network because it looks legitimate. Once connected, the attacker can see all of the customer's internet traffic. The customer logs into their email, Facebook, and bank account. The attacker captures the usernames and passwords. The attacker now has access to the customer's accounts. This is why you should always verify the exact network name and use a Virtual Private Network (VPN) on public Wi-Fi.

⚠️ How to Protect Against Network Threats
  • Use Encryption: Encrypt all sensitive data before sending it over the network. Use HTTPS for websites, TLS for email, and VPNs for remote access.
  • Use Firewalls: Firewalls block unauthorized traffic and prevent attackers from reaching vulnerable services.
  • Use Strong Authentication: Use multi factor authentication to prevent attackers from impersonating legitimate users even if they steal credentials.
  • Keep Systems Updated: Apply security patches promptly to close vulnerabilities that attackers could exploit.
  • Monitor Network Traffic: Use intrusion detection systems to detect attacks in progress.
  • Segment the Network: Divide the network into segments so that a compromise in one area does not give the attacker access to everything.
  • Train Employees: Educate employees about network threats such as evil twin attacks and phishing.
Key Takeaways for Topic 5.3

Threats to network communication include interception (packet sniffing, man in the middle), interruption (DDoS attacks), modification (tampering with data), and fabrication (spoofing, replay attacks, session hijacking). Other threats include port scanning and routing attacks. These threats can compromise the confidentiality, integrity, and availability of network data. Protection measures include encryption, firewalls, strong authentication, patching, monitoring, network segmentation, and employee training. On public networks, using a Virtual Private Network (VPN) is essential for protecting sensitive data.

Topic 5.4

Wireless Network Security

Wireless network security is the practice of protecting wireless networks from unauthorized access, eavesdropping, and attacks. Wireless networks are inherently less secure than wired networks because radio signals travel through the air and can be intercepted by anyone within range.
📌 Last Night Tip
Remember the evolution of Wi-Fi security protocols: Wired Equivalent Privacy (WEP) is broken (do not use), Wi-Fi Protected Access (WPA) is better but still vulnerable, Wi-Fi Protected Access 2 (WPA2) is standard but has KRACK vulnerability, Wi-Fi Protected Access 3 (WPA3) is the current strongest standard. Always use WPA2 or WPA3 with a strong password.

Why is Wireless Network Security Different?

Wireless networks are different from wired networks in several important ways.

  • No Physical Boundary: In a wired network, an attacker needs physical access to a network cable to intercept traffic. In a wireless network, radio signals travel through walls, ceilings, and floors. Anyone within range (often hundreds of meters with a good antenna) can attempt to intercept the signal.
  • Broadcast Nature: Wired networks send data only to the intended recipient. Wireless networks broadcast data through the air. Anyone listening can potentially receive the data.
  • Easy to Deploy but Hard to Secure: Setting up a wireless network is very easy. But securing it properly requires knowledge of encryption, authentication, and configuration.
  • Portable Devices: Wireless networks are often used with laptops, phones, and tablets that can be lost or stolen. Lost devices can give attackers access to the network.
Real World Example — Wireless Network Risk

Example: A Coffee Shop Wi-Fi A coffee shop offers free Wi-Fi to customers. The signal reaches the coffee shop, the parking lot, the street outside, and the apartment building across the street. Anyone within range can attempt to connect to the network. If the network has no password or uses weak encryption, anyone can see all the traffic of all customers. This is why you should never do banking or enter passwords on public Wi-Fi without a Virtual Private Network (VPN).

Wireless Security Protocols

Wireless networks use protocols to encrypt data and authenticate users. The following protocols have been developed over time, each improving security.

Wired Equivalent Privacy (WEP)

Wired Equivalent Privacy was the original security protocol for Wi-Fi networks, introduced in 1999. It was designed to provide the same level of privacy as a wired network.

Security Level: Very weak (broken)

Why it is insecure: Wired Equivalent Privacy uses a weak encryption algorithm called RC4. The same encryption keys are used for all traffic (no per packet keys). Attackers can crack a Wired Equivalent Privacy key in minutes using freely available tools. Wired Equivalent Privacy should never be used.

Attack: An attacker can capture enough packets and use tools like Aircrack ng to recover the password in less than one minute.

Wi-Fi Protected Access (WPA)

Wi-Fi Protected Access was introduced in 2003 as a temporary improvement over Wired Equivalent Privacy while the final 802.11i standard was being developed. It uses Temporal Key Integrity Protocol (TKIP) for encryption.

Security Level: Weak (better than Wired Equivalent Privacy but still vulnerable)

Why it is insecure: Wi-Fi Protected Access uses the same RC4 encryption as Wired Equivalent Privacy but adds per packet keys. However, vulnerabilities have been discovered. The KRACK attack can break WPA in some configurations.

Wi-Fi Protected Access 2 (WPA2)

Wi-Fi Protected Access 2 was introduced in 2004 and is the current standard for most networks. It uses the Advanced Encryption Standard (AES) for encryption, which is much stronger than RC4. Wi-Fi Protected Access 2 also uses stronger authentication methods.

Security Level: Strong (but has known vulnerabilities)

Limitations: Wi-Fi Protected Access 2 Personal (used in homes) is vulnerable to dictionary attacks if the password is weak. The KRACK attack (Key Reinstallation Attack) discovered in 2017 can break WPA2 under certain conditions. However, these attacks have been patched in most modern devices.

Recommendation: Use Wi-Fi Protected Access 2 with a strong password (at least twelve characters, mixed case, numbers, symbols). Keep devices updated with the latest patches.

Wi-Fi Protected Access 3 (WPA3)

Wi-Fi Protected Access 3 was introduced in 2018 as the replacement for Wi-Fi Protected Access 2. It includes several significant security improvements.

Security Level: Very strong (current best practice)

Improvements over Wi-Fi Protected Access 2:

  • Simultaneous Authentication of Equals (SAE) replaces Pre Shared Key (PSK), making dictionary attacks much harder
  • Individualized data encryption (each device has its own encryption key)
  • Stronger encryption (192 bit security mode for government and enterprise)
  • Better protection for open networks (Opportunistic Wireless Encryption)

Recommendation: Use Wi-Fi Protected Access 3 if all your devices support it. Otherwise, use WPA2 with a strong password.

Common Wireless Network Attacks

Evil Twin Attack

An attacker sets up a fake Wi-Fi access point with a name similar to a legitimate network. Users connect to the fake network because it looks legitimate. The attacker can then intercept all traffic, steal passwords, and inject malware.

Protection: Verify the exact network name. Use a Virtual Private Network (VPN) on public Wi-Fi. Use Wi-Fi Protected Access 3 or WPA2 Enterprise which authenticates the network, not just the user.

KRACK Attack (Key Reinstallation Attack)

The Key Reinstallation Attack exploits a weakness in the Wi-Fi Protected Access 2 handshake process. The attacker forces the device to reinstall an already used encryption key, resetting the nonce and replay counter. This allows the attacker to decrypt and replay packets.

Protection: Apply security patches to all devices and access points. Most vendors have released patches. Use Wi-Fi Protected Access 3 which is not vulnerable to this attack.

Dictionary Attack on Wi-Fi Password

Attackers capture the Wi-Fi Protected Access 2 handshake (the initial exchange when a device connects) and then try thousands of passwords from a dictionary to find the correct one. Weak passwords can be cracked in hours or days.

Protection: Use a strong, random password. A twelve character password with mixed case, numbers, and symbols would take many years to crack.

Deauthentication Attack

The attacker sends deauthentication frames (which tell a device to disconnect from the access point) to a connected client. The client disconnects and then reconnects. The attacker captures the handshake during reconnection.

Protection: Use management frame protection (802.11w) which is available in Wi-Fi Protected Access 2 and Wi-Fi Protected Access 3. Keep devices updated.

Jamming Attack

An attacker floods the wireless frequency with noise or interference, making it impossible for legitimate devices to communicate. This is a denial of service attack against the wireless network.

Protection: Jamming is difficult to prevent because wireless frequencies are shared. Use frequency hopping or switch to a different channel. In extreme cases, use a wired connection for critical systems.

Rogue Access Point

An attacker or an employee plugs an unauthorized access point into the wired network. This access point is not managed by the organization and may have weak security. Attackers can connect to the rogue access point and then access the internal network.

Protection: Use wireless intrusion prevention systems (WIPS) to detect rogue access points. Use network access control to prevent unauthorized devices from connecting to the network. Physically secure network ports.

Best Practices for Wireless Network Security

🔒

Use Strong Encryption

Never use Wired Equivalent Privacy. Use Wi-Fi Protected Access 2 or Wi-Fi Protected Access 3 with Advanced Encryption Standard (AES) encryption. Do not use Temporal Key Integrity Protocol (TKIP) because it is weaker.

🔑

Use a Strong Password

The Wi-Fi password should be at least twelve characters long and include uppercase letters, lowercase letters, numbers, and special characters. Do not use dictionary words or personal information. A strong password prevents dictionary attacks.

🔄

Change Default Settings

Change the default administrator password on the wireless router or access point. Change the default network name (Service Set Identifier or SSID). Disable remote administration. Disable Wi-Fi Protected Setup (WPS) because it has known vulnerabilities.

📡

Disable SSID Broadcasting

Disabling Service Set Identifier (SSID) broadcast prevents the network name from appearing in the list of available networks. This is security by obscurity (not strong on its own) but it adds a layer of difficulty for casual attackers.

👥

Use MAC Address Filtering

Media access control (MAC) address filtering allows only specific devices to connect to the network. This is not strong because MAC addresses can be spoofed, but it adds another layer of protection.

📶

Reduce Signal Strength

If possible, reduce the power of the wireless transmitter so the signal does not extend beyond the building. This reduces the number of people who can attempt to attack the network.

✂️

Segment the Wireless Network

Place guest Wi-Fi on a separate network segment from the main business network. Guest users should not have access to internal servers, printers, or sensitive data. This is called network segmentation.

🛡️

Use a Virtual Private Network (VPN)

Even on a trusted wireless network, use a Virtual Private Network (VPN) for sensitive activities. The Virtual Private Network (VPN) adds an additional layer of encryption and authentication.

🔄

Keep Firmware Updated

Wireless routers and access points receive firmware updates that fix security vulnerabilities. Check for updates regularly and install them promptly. Many devices now support automatic updates.

📋

Use WPA2 Enterprise or WPA3 Enterprise

For businesses, use the Enterprise version of Wi-Fi Protected Access 2 or Wi-Fi Protected Access 3. Enterprise mode uses a Remote Authentication Dial In User Service (RADIUS) server to authenticate each user individually with their own username and password. This is much more secure than using a shared password for everyone.

📊

Monitor the Wireless Network

Use wireless intrusion prevention systems (WIPS) to monitor for rogue access points, evil twin attacks, and other wireless threats. Log and investigate unusual activity.

Example — Configuring a Secure Home Wi-Fi Network

Step by Step Configuration:

  1. Log into the router's administration page (usually at 192.168.1.1 or 192.168.0.1).
  2. Change the default administrator password to a strong, unique password.
  3. Change the network name (SSID) to something that does not identify you personally.
  4. Set the security mode to Wi-Fi Protected Access 2 with Advanced Encryption Standard (WPA2-PSK AES) or Wi-Fi Protected Access 3 (WPA3) if available.
  5. Set a strong Wi-Fi password (at least twelve characters, mixed case, numbers, symbols).
  6. Disable Wi-Fi Protected Setup (WPS).
  7. Disable remote administration (so you can only configure the router from inside your network).
  8. Enable the firewall on the router.
  9. Check for and install any firmware updates.
  10. Create a separate guest network for visitors.
⚠️ What Not to Do
  • Do not use Wired Equivalent Privacy (WEP). It can be cracked in minutes.
  • Do not use an open network (no password) unless you have a specific reason and use a Virtual Private Network (VPN).
  • Do not leave the default administrator password on the router.
  • Do not use a weak password like "password" or "12345678".
  • Do not ignore firmware update notifications.
  • Do not assume that Wi-Fi Protected Access 2 is completely secure. Use a Virtual Private Network (VPN) for sensitive activities.
  • Do not connect to unknown or suspicious Wi-Fi networks.
Unit 5 — Key Takeaway

Securing operating systems and networks is essential for protecting information assets. Operating system security includes authentication, authorization, auditing, memory protection, user account control, and patch management. Rootkits are sophisticated malware that hide from the operating system, requiring specialized anti rootkit tools for detection. Threats to network communication include interception, interruption, modification, and fabrication attacks such as packet sniffing, man in the middle, spoofing, replay attacks, session hijacking, and denial of service attacks. Wireless networks present unique security challenges because radio signals travel through the air. Strong wireless security requires using Wi-Fi Protected Access 2 or Wi-Fi Protected Access 3 encryption, strong passwords, updated firmware, network segmentation, and monitoring. A defense in depth approach combining multiple layers of security provides the best protection.
