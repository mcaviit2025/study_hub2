Question 1 · Part A

What is Domain Name System? Explain its purpose.

5 Marks
Domain Name System (DNS) is a hierarchical naming system for computers, services, and other resources connected to the internet or a private network. It translates human-readable domain names (like www.google.com) into numerical IP addresses (like 142.250.183.46) that computers use to identify each other.

What is Domain Name System?

The Domain Name System is often called the "phonebook of the internet." Just as you look up a person's name to find their phone number, computers look up a domain name to find its IP address. Without DNS, users would have to remember long strings of numbers for every website they want to visit.

Real World Example

When you type "www.sppu.ac.in" in your browser, your computer does the following:

  1. Checks its local DNS cache to see if it already knows the IP address.
  2. If not, it asks your Internet Service Provider's DNS server.
  3. That server queries other DNS servers across the internet.
  4. Finally, it receives the IP address (example: 202.88.130.42) and your browser connects to that address.
  5. The entire process takes milliseconds and happens without you noticing.

Purpose of Domain Name System

  • Human Readable Names: The main purpose of DNS is to allow users to use easy to remember domain names instead of difficult to remember IP addresses. It is much easier to remember "www.amazon.in" than "205.251.242.103".
  • IP Address Resolution: DNS converts domain names to IP addresses (forward lookup) and can also convert IP addresses to domain names (reverse lookup).
  • Load Distribution: DNS can return different IP addresses for the same domain name to distribute traffic across multiple servers. This helps with load balancing and high availability.
  • Email Routing: DNS is used to route email by providing Mail Exchange (MX) records that tell email servers where to deliver email for a particular domain.
  • Decentralized Database: DNS provides a distributed, hierarchical database of domain information. No single organization controls all DNS data, making the system resilient and fault-tolerant.

  • RFC 1034 & RFC 1035 — Domain Names: Concepts and Facilities
  • ICANN DNS Resource: https://www.icann.org/resources/pages/dns-2012-02-25-en
Question 1 · Part B

Explain the role and importance of virtualization in Information Security.

5 Marks
Virtualization is the technology that allows multiple virtual machines to run on a single physical computer, each with its own operating system and applications. A thin software layer called the hypervisor manages these virtual machines and isolates them from each other. In information security, virtualization plays a crucial role in isolation, testing, and protection.

Role of Virtualization in Information Security

  • Isolation and Sandboxing: Each virtual machine is completely isolated from others. If one virtual machine gets infected with malware, the hypervisor prevents it from spreading to other virtual machines on the same physical server. Security analysts run suspicious files inside an isolated "sandbox" virtual machine. If the file is malware, only that virtual machine is harmed.
  • Secure Testing Environments: Organizations can create virtual copies of their production systems to test security patches, new configurations, or software updates before deploying them to live systems. This eliminates the risk of breaking production systems.
  • Honeypots: Virtual machines can be configured as decoys (honeypots) to attract attackers. Security teams can observe attacker behavior without risking real systems.
  • Disaster Recovery: Virtual machines can be backed up and restored quickly. If a system is compromised by ransomware, the organization can revert to a clean snapshot from before the attack within minutes.
  • Network Segmentation: Virtual networks can be created to isolate sensitive systems from less secure ones, even when they run on the same physical hardware.

Importance of Virtualization in Information Security

  • Cost Effective Security Testing: Without virtualization, testing security patches would require separate physical computers for each test. Virtualization allows many test environments on a single physical server, saving significant cost.
  • Rapid Incident Response: When a system is compromised, a clean virtual machine snapshot can be deployed in minutes instead of hours or days needed to rebuild a physical server.
  • Forensic Analysis: Security investigators can take snapshots of compromised virtual machines and analyze them without altering the original evidence. The entire state of the system is preserved.
  • Training and Education: Security professionals can practice attacks and defenses in virtual environments without risking real systems.
  • Separation of Duties: Different security functions can run on separate virtual machines on the same hardware, providing logical isolation without additional physical servers.
Real World Example

A bank receives a suspicious email attachment. Instead of opening it on a real computer, the security team runs it in a virtual machine. The attachment turns out to be ransomware that encrypts all files. Because the ransomware is running in a virtual machine, it only encrypts the virtual machine's files. The host computer and the bank's network remain completely safe. The security team can then study the ransomware to understand how it works and develop defenses.

Question 1 · Part C

What is information assurance? Why do we need information assurance?

5 Marks
Information Assurance (IA) is the practice of managing risks related to the use, processing, storage, and transmission of information. It ensures that information systems are reliable and that the information they contain is trustworthy. Information Assurance goes beyond security to include the overall trustworthiness of information.

What is Information Assurance?

Information Assurance is built on five pillars: Integrity, Availability, Confidentiality, Authentication, and Non-Repudiation.

  • Integrity: Information is accurate and has not been tampered with.
  • Availability: Information is accessible when authorized users need it.
  • Confidentiality: Information is protected from unauthorized access.
  • Authentication: The identity of users is verified.
  • Non-Repudiation: A person cannot deny having performed an action.
Fig 1.1 — Five Pillars of Information Assurance

Why Do We Need Information Assurance?

  • Trustworthy Decision Making: Organizations make decisions based on information. If the information is not trustworthy (inaccurate, incomplete, or tampered with), decisions will be wrong. Information Assurance ensures that decision makers can trust the information they use.
  • Legal and Regulatory Compliance: Laws such as the Digital Personal Data Protection Act 2023 require organizations to protect personal data and ensure its accuracy. Information Assurance helps organizations meet these legal requirements.
  • Protection of Reputation: When an organization's information is compromised or found to be unreliable, customer trust is damaged. Information Assurance protects the organization's reputation by ensuring information is reliable.
  • Business Continuity: Information Assurance ensures that critical information is available when needed, even during disruptions. This supports business continuity and disaster recovery.
  • Risk Management: Information Assurance provides a framework for identifying, assessing, and managing risks to information assets. This helps organizations prioritize their security investments.
Real World Example

A hospital uses Information Assurance to ensure patient records are accurate (integrity), available to doctors when needed (availability), kept confidential from unauthorized people (confidentiality), verified as coming from legitimate sources (authentication), and documented so no one can deny changing a record (non-repudiation). Without Information Assurance, a doctor might make a treatment decision based on an incorrect or outdated patient record, with potentially fatal consequences.

Question 1 · Part D

Explain Microsoft security principles in short.

5 Marks
Microsoft Security Principles are a set of guidelines that Microsoft uses to design, develop, and operate secure software and systems. These principles are based on decades of experience in building software used by billions of people worldwide.

Key Microsoft Security Principles

  • Security by Design: Security must be built into software from the beginning, not added at the end. This means security requirements are considered during the design phase, not after coding is complete.
  • Security by Default: Software should be secure in its default configuration. Users should not have to change settings to be secure. This means disabling unnecessary features, using strong encryption by default, and requiring authentication.
  • Security by Deployment: Software must provide guidance and tools to help customers deploy and operate it securely. This includes security configuration guides, automated tools, and best practice documentation.
  • Assume Breach: Design systems assuming that attackers are already inside the network. This means using multiple layers of security, monitoring for suspicious activity, and limiting the damage any single compromise can cause.
  • Least Privilege: Users and processes should have only the minimum permissions necessary to perform their functions. No one should have extra permissions they do not need.
  • Defense in Depth: Use multiple layers of security controls so that if one layer fails, other layers still provide protection. For example, use firewalls, encryption, access controls, and monitoring together.
  • Secure by Design, Secure by Default, Secure by Deployment: This is Microsoft's core security mantra. It emphasizes that security must be considered at every stage from design to deployment.
Example in Practice — Windows Operating System

Microsoft applies these principles in Windows:

  • Security by Design: Windows 11 was designed with hardware based isolation and secure boot from the start.
  • Security by Default: Windows Defender antivirus is enabled by default. Users do not need to install additional antivirus software.
  • Security by Deployment: Microsoft provides tools like Windows Update for Business to help organizations deploy security patches.
  • Assume Breach: Windows includes features like Credential Guard that protect login credentials even if the system is compromised.
  • Least Privilege: User Account Control prompts for permission before making system changes.

Question 2 · Part A

Describe the different types of Information Security threats to an organisation.

5 Marks
Information Security Threats are any potential dangers that could harm an organization's information assets. These threats can come from various sources and take many forms. Understanding these threats is essential for implementing appropriate security controls.

Types of Information Security Threats

  • Malware (Malicious Software): Software designed to harm or gain unauthorized access to systems. Types include viruses (self replicating code), worms (spread without user action), Trojans (disguised as legitimate software), ransomware (encrypts data and demands payment), and spyware (collects information secretly).
  • Phishing Attacks: Attacks that trick users into revealing sensitive information or clicking malicious links. Spear phishing targets specific individuals, whaling targets senior executives, and smishing uses text messages.
  • Insider Threats: Threats from within the organization. Malicious insiders deliberately misuse access for personal gain or revenge. Negligent insiders accidentally cause breaches through careless actions such as losing laptops or falling for phishing.
  • Denial of Service (DoS) and Distributed Denial of Service (DDoS) Attacks: Attacks that overwhelm systems with traffic, making them unavailable to legitimate users. These attacks can disrupt business operations and cause significant financial loss.
  • Man in the Middle Attacks: Attacks where an attacker intercepts and potentially modifies communication between two parties. The parties believe they are communicating directly, but the attacker controls the conversation.
  • SQL Injection: Attacks that insert malicious SQL code into database queries through vulnerable input fields. Attackers can read, modify, or delete database data.
  • Cross Site Scripting (XSS): Attacks that inject malicious scripts into websites viewed by other users. The scripts run in victims' browsers and can steal cookies, session tokens, or other sensitive information.
  • Password Attacks: Attacks that attempt to obtain or crack passwords. Methods include brute force (trying all combinations), dictionary attacks (trying common words), credential stuffing (using passwords stolen from other sites), and keylogging (recording keystrokes).
  • Advanced Persistent Threats (APTs): Sophisticated, long term attacks typically carried out by nation state actors. Attackers gain access and remain undetected for months or years, slowly stealing sensitive information.
  • Social Engineering: Attacks that manipulate people into revealing information or performing actions. This includes pretexting (creating a false scenario), baiting (offering something enticing), and tailgating (following authorized people into secure areas).
Real World Example — Multiple Threats Combined

A typical data breach often involves multiple threats. For example: An employee receives a phishing email (social engineering). The email contains a link that downloads malware (malware). The malware captures the employee's password (password attack). The attacker then moves through the network (insider threat using stolen credentials) and steals customer data. The organization only discovers the breach months later because the attacker covered their tracks (APT techniques).

Question 2 · Part B

How do reporting techniques in IT auditing help to identify and address the security vulnerabilities in an organisation?

5 Marks
IT auditing reporting techniques are methods used to document, communicate, and track security findings discovered during an audit. These techniques transform raw audit data into actionable information that management can use to improve security.

How Reporting Techniques Help Identify Vulnerabilities

  • Executive Summaries: Provide a high level overview of security posture for senior management. This helps leaders understand the most critical vulnerabilities without reading technical details. Executive summaries highlight the top risks that need immediate attention.
  • Findings Tables: Organize vulnerabilities in a structured format showing the finding, risk level, recommendation, responsible person, and due date. This makes it easy to track which vulnerabilities exist and who is responsible for fixing them.
  • Risk Heat Maps: Visual representations of risk that use colors to show severity (red for high risk, yellow for medium, green for low). Heat maps help management quickly identify which areas need immediate attention.
  • Gap Analysis Reports: Compare current security controls against industry standards or regulatory requirements. Gap analysis explicitly shows what is missing and what needs to be implemented.
  • Trend Analysis: Track vulnerabilities over time to see if security is improving or worsening. Trend reports show whether the number of open vulnerabilities is increasing or decreasing.

How Reporting Techniques Help Address Vulnerabilities

  • Clear Recommendations: Audit reports do not just identify problems. They provide specific, actionable recommendations for fixing each vulnerability. For example, "Install security patch KB5012345 on all Windows servers by March 31."
  • Assignment of Responsibility: Reporting techniques assign specific individuals or teams to address each vulnerability. This creates accountability and ensures vulnerabilities do not fall through the cracks.
  • Tracking and Follow Up: Reports track the status of each finding (open, in progress, fixed, accepted risk). Management can see which vulnerabilities have been addressed and which remain open.
  • Prioritization: Reports rank vulnerabilities by risk level. This helps organizations allocate limited resources to the most critical vulnerabilities first.
  • Evidence for Management Action: Formal audit reports provide documented evidence that management needs to justify security spending. When a manager requests budget for a firewall, the audit report provides justification.
Example — Audit Report Finding

Finding: Critical security patch missing on customer database server.

Risk Level: High (Exploitable vulnerability allows remote code execution)

Recommendation: Apply security patch KB5012345 within 7 days.

Responsible: Database Administrator

Due Date: January 31, 2026

Status: Open

This clear, actionable finding ensures the vulnerability is properly tracked and addressed.

  • ISACA: IT Audit Reporting Standards
  • IIA (Institute of Internal Auditors) Standards for Reporting

Question 2 · OR · Part C

Explain various roles of IT auditing in ensuring information security.

5 Marks
IT auditing plays a critical role in ensuring information security by providing independent assessment, identifying weaknesses, verifying compliance, and recommending improvements.

Various Roles of IT Auditing in Information Security

  • Independent Assessment Role: IT auditors provide an objective, unbiased evaluation of security controls. Unlike internal security teams who may have conflicts of interest or blind spots, auditors bring fresh perspective and independence.
  • Compliance Verification Role: Auditors verify that the organization complies with laws, regulations, and standards such as the Digital Personal Data Protection Act 2023, Payment Card Industry Data Security Standard (PCI DSS), and ISO 27001. This role helps organizations avoid fines and legal penalties.
  • Vulnerability Identification Role: Auditors use specialized tools and techniques to identify security vulnerabilities that internal teams may have missed. This includes vulnerability scanning, penetration testing, and configuration reviews.
  • Risk Assessment Role: Auditors assess the organization's security risks by evaluating threats, vulnerabilities, and impacts. They help prioritize which risks need immediate attention based on likelihood and potential damage.
  • Control Testing Role: Auditors test whether security controls are working as intended. For example, they attempt to bypass access controls, verify that logs are being collected, and confirm that backups can be restored.
  • Advisory and Recommendation Role: Auditors provide recommendations for improving security based on industry best practices and their audit findings. These recommendations help organizations strengthen their security posture.
  • Assurance Role: Auditors provide assurance to management, the board of directors, and external stakeholders that security controls are adequate. This assurance builds trust in the organization's security program.
  • Forensic and Investigation Role: When security incidents occur, auditors may investigate to determine what happened, how it happened, and what data was affected. This role supports incident response and legal proceedings.
Real World Example

A bank's internal security team believes their firewalls are properly configured. An IT auditor reviews the firewall rules and discovers that a rule intended for testing was left active, allowing traffic from the internet to reach the internal database server. The auditor's independent assessment identified a critical vulnerability that the internal team had missed. The auditor recommends removing the test rule immediately. The bank addresses the vulnerability before attackers discover it.

Official References
  • ISACA: IT Audit Framework (ITAF)
  • NIST SP 800-53A (Assessing Security Controls)
Question 2 · OR · Part D

How does information assurance differ from information security? How do both contribute to the overall security posture of an organisation?

5 Marks
Information Assurance (IA) and Information Security (InfoSec) are related but distinct concepts. Understanding the difference is important for building a comprehensive security program.

Differences Between Information Assurance and Information Security

AspectInformation AssuranceInformation Security
Primary FocusTrustworthiness and reliability of informationProtection of information from unauthorized access
Key QuestionCan we trust this information to make decisions?Is this information protected from attackers?
ScopeBroader — includes security plus integrity, authenticity, and non-repudiationNarrower — focuses on confidentiality, integrity, availability
Key ComponentsFive pillars: Integrity, Availability, Confidentiality, Authentication, Non-RepudiationCIA Triad: Confidentiality, Integrity, Availability

How Both Contribute to Overall Security Posture

  • Complementary Roles: Information Security protects information from external and internal threats. Information Assurance ensures the protected information is actually trustworthy. Together, they provide both protection and confidence.
  • Risk Management: Information Security identifies and mitigates risks to information assets. Information Assurance ensures that risk mitigation efforts are effective and that residual risk is understood. Together, they provide a complete risk management framework.
  • Compliance: Information Security helps meet regulatory requirements for data protection. Information Assurance helps meet requirements for data accuracy and reliability. Together, they support comprehensive compliance.
  • Business Enablement: Information Security enables business by protecting sensitive data so the organization can operate safely. Information Assurance enables business by ensuring decision makers can trust the information they use. Together, they support confident business operations.
Simple Analogy

Information Security is like a bank vault. It keeps money safe from thieves. Information Assurance is like an accountant. It ensures the bank's records are accurate and that the money in the vault matches what the records say. Both are essential. A strong vault (Information Security) does not help if the records are wrong (lack of Information Assurance). Accurate records (Information Assurance) do not help if thieves can steal the money (lack of Information Security).

Question 3 · Part A

Tech Startup: Security Policy & Application Security

7 Marks
A tech startup is growing rapidly and handling sensitive customer data, API keys and intellectual property. However, the company does not have a documented security policy, leading to data leaks, weak passwords and insider threats. The CEO has now asked the security team to come up with a formal information security policy.

Part (i) — Essential Key Elements of Security Policy to be Developed

  • Data Classification and Handling Policy: Defines how different types of data (customer data, API keys, intellectual property) should be handled. Customer data must be encrypted. API keys must never be stored in code or shared. Intellectual property must have access restrictions. This policy directly addresses the data leak risk.
  • Password Policy: Requires strong passwords (minimum twelve characters, mixed case, numbers, special characters). Requires multi-factor authentication for all systems. Prohibits password reuse and sharing. Requires regular password changes every ninety days. This policy directly addresses the weak password risk.
  • Access Control Policy: Implements the principle of least privilege (users only get the access they need). Requires regular access reviews (quarterly). Requires immediate removal of access when employees leave. This policy directly addresses the insider threat risk.
  • Acceptable Use Policy: Defines what employees can and cannot do with company systems. Prohibits installing unauthorized software. Prohibits accessing personal email on work computers. Prohibits sharing confidential information with unauthorized people.
  • Security Awareness and Training Policy: Requires all employees to complete security training upon hiring and annually thereafter. Training must cover password security, phishing detection, data handling, and incident reporting. Creates accountability for employee behavior.
  • Incident Response Policy: Defines what constitutes a security incident, who must be notified, and what steps to take. Specifies how to report suspected data leaks. This ensures quick response when problems occur.
  • API Key Management Policy: Specific policy for API keys. Requires keys to be stored in secure vaults, not in code. Requires regular key rotation. Requires access logging for all key usage. This directly addresses the API key risk.

Part (ii) — How the Newly Developed Policy Will Ensure Application Security

  • Secure Development Requirements: The security policy will require that all applications be developed using secure coding practices. This includes input validation to prevent SQL injection, output encoding to prevent cross-site scripting, and proper authentication and authorization mechanisms.
  • Regular Security Testing: The policy will require regular application security testing including vulnerability scans, static code analysis, and penetration testing before each major release. This ensures vulnerabilities are found and fixed before attackers can exploit them.
  • API Security Controls: The policy will require that all APIs be protected with authentication, rate limiting, and input validation. API keys must be rotated regularly and stored securely. All API access must be logged. This directly protects the startup's API keys and intellectual property.
  • Data Protection in Applications: The policy will require that all customer data be encrypted both when stored (at rest) and when transmitted (in transit). Applications must not log sensitive data. This prevents data leaks through application logs or network interception.
  • Secure Software Development Lifecycle (SSDLC): The policy will mandate that security is integrated into every phase of development — threat modeling during design, static code analysis during development, penetration testing before release, and runtime monitoring in production.
Immediate Actions for the Startup

The startup should: 1) Draft and approve the security policy within 30 days, 2) Train all employees on the new policy, 3) Require signed acknowledgment from every employee, 4) Implement technical controls (MFA, password policy, access reviews) within 60 days, and 5) Conduct an external security audit within 90 days.

Official References
  • NIST SP 800-53 (Security and Privacy Controls)
  • OWASP Application Security Verification Standard (ASVS)
Question 3 · Part B

Write short note on: Application Security.

3 Marks
Application Security (AppSec) is the practice of protecting software applications from security threats throughout their entire lifecycle. This includes designing secure applications, writing secure code, testing for vulnerabilities, and monitoring applications in production.

Key Aspects of Application Security

  • Secure Coding: Writing code that avoids common vulnerabilities such as SQL injection, cross-site scripting, and buffer overflows. Secure coding standards and guidelines help developers write safer code.
  • Security Testing: Testing applications for vulnerabilities using static analysis (analyzing source code), dynamic analysis (testing running applications), and penetration testing (simulating real attacks).
  • Authentication and Authorization: Ensuring only legitimate users can access the application (authentication) and that users can only access what they are permitted to (authorization). Multi-factor authentication is increasingly required.
  • Input Validation: Checking all data received from users to ensure it is safe before processing. This prevents injection attacks and other input-based vulnerabilities.
  • Output Encoding: Encoding data before displaying it in web pages to prevent cross-site scripting attacks where attackers inject malicious scripts.
  • OWASP Top 10: The Open Web Application Security Project (OWASP) publishes a list of the ten most critical web application security risks. Following OWASP guidance is considered best practice for application security.
Example

A banking application implements application security by: requiring multi-factor authentication for login (authentication), checking that users can only see their own accounts (authorization), validating that account numbers are numeric and within range (input validation), and encrypting all sensitive data (data protection). Regular penetration testing ensures new vulnerabilities are found and fixed.

Official References
  • OWASP Top 10: https://owasp.org/Top10
  • NIST SP 800-218 (Secure Software Development Framework)

Question 3 · OR · Part C

CISO: Information Security Governance Principles & Policy Elements

7 Marks
Imagine you are the Chief Information Security Officer (CISO) of an organisation. You are supposed to apply the principles of information security governance to create a framework that ensures the security policies and practices are aligned with the organisation's overall business goals and compliance requirements.

Part (i) — Principles of Information Security Governance

  • Strategic Alignment: Security activities must support business goals and objectives. Security should enable the business to achieve its goals safely, not hinder operations. The CISO must understand business priorities and align security investments accordingly.
  • Risk Management: The organization must have a formal process for identifying, assessing, and managing security risks. Risks must be prioritized based on likelihood and impact. Risk decisions must be made at the appropriate management level.
  • Resource Management: Security resources (people, budget, technology) must be allocated effectively and efficiently. Resources should be directed to the highest priority risks. The CISO must justify resource requests based on business value and risk reduction.
  • Performance Measurement: The organization must measure whether security is working. Metrics such as number of incidents, time to detect, time to respond, and compliance rates must be tracked and reported to management. Without measurement, improvement is impossible.
  • Value Delivery: Security investments must deliver value to the organization. Every rupee spent on security should reduce risk by more than it costs. The CISO must demonstrate return on security investment.
  • Compliance: The organization must comply with all applicable laws, regulations, and contractual obligations. This includes data protection laws, industry standards, and customer contracts. Compliance must be documented and auditable.
  • Accountability: Security responsibilities must be clearly assigned to specific individuals. Senior management must be accountable for security outcomes. The CISO must report regularly to the board of directors.
  • Integration: Security must be integrated into all business processes, not treated as a separate activity. Security should be part of project management, procurement, human resources, and operations.

Part (ii) — Key Elements of Information Security Policy to be Considered

  • Purpose and Scope: Clearly state why the policy exists and who it applies to. The scope should include all employees, contractors, vendors, and third parties who access organizational systems.
  • Roles and Responsibilities: Define who is responsible for implementing, enforcing, and complying with the policy. This includes the CISO, IT department, managers, and individual employees.
  • Specific Policy Statements: Clear, actionable rules that employees must follow. For example, "All passwords must be at least twelve characters long" rather than "Use strong passwords."
  • Consequences of Violation: State what happens if the policy is violated. Consequences may include verbal warnings, written warnings, suspension, termination, or legal action.
  • Review and Update Schedule: Specify how often the policy will be reviewed and updated. Most organizations review policies annually or when significant changes occur.
  • Acknowledgment: Require employees to sign a form acknowledging they have read and understood the policy. This creates accountability.
CISO Role Summary

The CISO must establish a governance framework with board oversight, risk management processes, security metrics, and clear accountability. Security policies must be practical, enforceable, and aligned with business objectives. Regular audits and continuous improvement are essential for mature security governance.

Official References
  • ISO/IEC 38500 (Governance of IT)
  • ISACA: COBIT 2019 Governance Framework
  • NIST Cybersecurity Framework — Governance (GV) Function
Question 3 · OR · Part D

Write short note on security architecture in information system.

3 Marks
Security Architecture is the high-level structure of security controls within an information system. It is the blueprint that describes how security components such as firewalls, intrusion detection systems, encryption, and access controls work together to protect the system.

Key Elements of Security Architecture

  • Defense in Depth: Multiple layers of security controls arranged so that if one layer fails, another layer provides protection. For example, firewalls at the network perimeter, intrusion detection inside the network, encryption for data, and access controls for applications.
  • Least Privilege: Every user, process, and system has only the minimum privileges necessary to perform its function. No one has extra permissions.
  • Network Segmentation: Dividing the network into smaller, isolated segments. If an attacker compromises one segment, they cannot easily reach other segments containing sensitive data.
  • Zero Trust Architecture: A modern approach that assumes no user or device is trustworthy, even inside the network. Every access request must be verified, authenticated, and authorized.
  • Security Controls: The actual measures implemented including firewalls, intrusion detection systems, encryption, authentication systems, and monitoring tools.
Example — Security Architecture for a Bank

A bank's security architecture includes: a perimeter firewall blocking internet threats, an internal firewall separating the customer database network, encryption for all customer data, multi-factor authentication for all users, intrusion detection systems monitoring traffic, and a security information and event management system collecting logs. This layered architecture protects the bank even if one control fails.

Official References
  • NIST SP 800-160 (Systems Security Engineering)
  • Zero Trust Architecture (NIST SP 800-207)
Question 4 · Part A

Government Agency: Phishing Attacks & Email Security Policies

7 Marks
Employees of a government agency received fake emails pretending to be from senior officials, asking them to click on malicious links. As a result, hackers gained access to classified government documents and citizen records. The agency did not have a security awareness training policy and employees were not trained to identify various security threats.

Part (i) — Various Attacks from the Above Scenario

  • Phishing Attack: The fake emails pretending to be from senior officials are a classic phishing attack. This specific type is called "spear phishing" because the emails were targeted at a specific organization (the government agency) and impersonated specific individuals (senior officials).
  • Social Engineering: The attackers manipulated human psychology by pretending to be authority figures. People are more likely to trust and obey requests from senior officials. This psychological manipulation is social engineering.
  • Malware Distribution: The malicious links likely led to websites that downloaded malware onto the employees' computers. Common types include keyloggers (capture passwords), remote access Trojans (give attackers control), or ransomware (encrypt files).
  • Data Exfiltration: After gaining access, the hackers stole classified government documents and citizen records. This is called data exfiltration or data theft.
Attack Chain Explanation

The complete attack chain was:

  1. Employees received fake emails that appeared to come from senior officials (phishing).
  2. Employees trusted the emails because they came from authority figures (social engineering).
  3. Employees clicked malicious links (social engineering success).
  4. Malware installed on their computers (malware attack).
  5. Hackers used the malware to gain access to the network.
  6. Hackers searched for and stole classified documents and citizen records (data exfiltration).

Part (ii) — How Email Security Policies Prevent Such Attacks

  • Email Filtering Policy: A policy requiring email filtering would have blocked many phishing emails before they reached employees. Filters can detect known malicious senders, suspicious links, and spoofed email addresses.
  • Sender Authentication Policy: A policy implementing email authentication standards (SPF, DKIM, DMARC) would have made it impossible for attackers to spoof the senior officials' email addresses. The fake emails would have been rejected as unauthenticated.
  • Link Safety Policy: A policy requiring that all links in emails be scanned and rewritten would have detected the malicious links. Employees would see a warning before clicking, or the link would be blocked entirely.
  • Attachment Handling Policy: A policy restricting attachment types and scanning all attachments for malware would have detected any malware sent as attachments.
  • Security Awareness Training Policy: The most important policy the agency lacked. A policy requiring regular security awareness training would have taught employees to: verify sender addresses, hover over links to see real destinations, never click unexpected links, report suspicious emails to the security team, and verify urgent requests through a different channel (such as a phone call).
  • Incident Reporting Policy: A policy requiring employees to report suspicious emails immediately would have allowed the security team to warn other employees and block the attack quickly.
How Policies Would Have Changed the Outcome

If the agency had email security policies in place: Sender authentication would have rejected the fake emails. If any emails did get through, trained employees would have recognized them as suspicious and reported them. The security team would have blocked the malicious links and warned all employees. No employee would have clicked the links, so no malware would have been installed. The hackers would not have gained access to classified documents or citizen records.

Question 4 · Part B

Write short note on Denial of Service Attack (DoS).

3 Marks
Denial of Service (DoS) Attack is an attack that aims to make a computer system, network, or service unavailable to its intended users. Attackers flood the target with excessive requests or exploit vulnerabilities to crash the system.

Types of Denial of Service Attacks

  • Volume Based Attacks: Overwhelm the target's network bandwidth with massive amounts of traffic. Examples include UDP floods and ICMP floods. The target's internet connection becomes completely saturated.
  • Protocol Attacks: Exploit weaknesses in network protocols to consume server resources. Examples include SYN floods (exhaust connection tables) and Ping of Death (send malformed packets).
  • Application Layer Attacks: Target specific applications or web pages. They send requests that appear legitimate but consume application resources such as database connections or CPU power. Examples include HTTP floods and Slowloris attacks.
  • Distributed Denial of Service (DDoS): A DoS attack launched from many sources simultaneously (often using a botnet of infected computers). DDoS attacks are much harder to stop because traffic comes from many different IP addresses.

Impact of Denial of Service Attacks

  • Business loses revenue (e-commerce sites cannot process orders).
  • Customer trust is damaged (users cannot access services).
  • Reputation suffers (company appears unreliable).
  • Remediation costs money (DDoS protection services, overtime for IT staff).
Example — DDoS Attack on a Bank

A bank's website is hit by a DDoS attack. The attackers send millions of requests per second from thousands of infected computers. The bank's servers cannot handle the traffic and become unresponsive. Customers cannot log in, check balances, or transfer money. The bank loses customer trust and faces regulatory scrutiny.

Bank Data Breach: Threats Exploited & Security Policy Implementation

7 Marks
A leading bank suffered a data breach where cyber criminals stole sensitive customer data including account details and credit card information. The investigation revealed that attackers exploited weak passwords, unpatched software vulnerabilities, and poor access controls. The bank did not have a robust information security policy in place to prevent such incidents.

Part (ii) — Security Policy to Mitigate Future Network Attacks

  • Strong Password and Authentication Policy: Mandate: minimum 12 characters, complexity (uppercase, lowercase, numbers, symbols), no common passwords, password expiration every 90 days, password history (can't reuse last 5 passwords). Implement multi-factor authentication (MFA) for all administrative and privileged accounts.
  • Vulnerability and Patch Management Policy: Establish a formal patch management process: Critical security patches applied within 48 hours, High severity patches within 14 days, Monthly vulnerability scanning of all systems, Quarterly penetration testing by external firm.

  • Incident Response and Breach Notification Policy: Documented IRP including: who to call (incident response team), containment steps, eradication, recovery, notification (customers, regulators within 6 hours), post-incident review.
  • Security Awareness Training Policy: All bank employees must complete annual cybersecurity training covering phishing recognition, password hygiene, social engineering, and reporting suspicious activity.
Accountability

The bank must assign a CISO with budget authority, conduct an external audit within 60 days, and report findings to the board. Regulators (RBI) should be notified of the breach and remediation plan.

Question 4 · OR · Part D

Write short note on Email Security.

3 Marks
Email Security refers to the collective measures used to secure email communications, accounts, and content against threats like phishing, spam, malware, spoofing, and data leakage. Email remains the number one attack vector in cybersecurity.

Key Email Security Threats

  • Phishing / Spear Phishing: Fake emails tricking users into credentials or malware
  • Business Email Compromise (BEC): Impersonating executives to request fraudulent wire transfers
  • Malware Attachments: Office documents or PDFs containing malicious macros
  • Email Spoofing: Forging the "From" address to impersonate a trusted sender
  • Spam: Unsolicited bulk email (often containing malicious links)

Email Security Controls

Authentication Protocols (Prevent Spoofing)

  • SPF (Sender Policy Framework): Specifies which servers can send emails for your domain
  • DKIM (DomainKeys Identified Mail): Digital signature to verify email integrity
  • DMARC (Domain-based Message Authentication): Tells receiving servers what to do if SPF/DKIM fails (quarantine or reject)

Technical Controls

  • Email Security Gateways: Filter incoming emails for spam, phishing, and malicious attachments
  • Sandboxing: Open attachments and links in an isolated environment to detect unknown threats
  • Email Encryption (TLS, S/MIME, PGP): Encrypt email content in transit and at rest
  • DLP (Data Loss Prevention): Prevent sensitive data from being emailed externally

Question 5 · Part A

Examine various security parameters for wireless network.

5 Marks
Wireless network security parameters are the configuration settings and security controls that determine how secure a wireless network is. Wireless is inherently less secure than wired because signals broadcast through the air and can be intercepted without physical access.

Security Parameters for Wireless Networks

  • Encryption Protocol (Most Important): Always use WPA3 (Wi-Fi Protected Access 3) — the current standard with 192-bit encryption, protection against brute-force attacks, and forward secrecy. If WPA3 unavailable, use WPA2-AES (not WPA-TKIP or WEP, which are broken).
  • Strong Authentication (Passphrase / 802.1X): WPA3-Personal uses Simultaneous Authentication of Equals (SAE) — resistant to offline dictionary attacks. Requires a long, complex passphrase (20+ random characters). WPA3-Enterprise (802.1X) uses individual username/password or certificates — best for organizations.
  • Hidden SSID (Limited Value): Disabling SSID broadcast hides the network name from casual users, but attackers can still discover it. This should be used only as a minor inconvenience, not a primary control.
  • MAC Address Filtering (Weak Control): Allow-listing specific device MAC addresses. Attackers can easily spoof MAC addresses — so this only stops casual users. Use only as an additional layer.
  • Client Isolation (Guest Networks): Enable AP Isolation on guest networks so that connected devices cannot see or attack each other. Each guest device can only reach the internet, not other internal devices.
  • Firmware and Driver Updates: Access points, routers, and wireless clients must receive regular security patches. Wireless vulnerabilities (e.g., KRACK, FragAttacks) are discovered regularly — unpatched devices remain vulnerable.
  • Disable Unnecessary Management Interfaces: Disable remote management (Telnet, HTTP) access from WAN/internet side. Use only local management (LAN side) or VPN + secure management interface on a dedicated VLAN.
  • Rogue Access Point Detection: Deploy wireless intrusion prevention (WIPS) that continuously scans for unauthorized APs. If an employee plugs in an unapproved personal router (creating a backdoor), WIPS detects and blocks it.

Question 5 · Part B

Illustrate threats to network communication.

5 Marks
Threats to network communication are attacks that target the transmission of data between computers, servers, and devices. These threats aim to intercept, modify, disrupt, or eavesdrop on network traffic.

Categories of Network Communication Threats

  • Interception (Eavesdropping): Attackers capture and read network traffic without modifying it. This is a threat to confidentiality. Examples include packet sniffing and man-in-the-middle attacks. On unencrypted networks, attackers can read passwords, emails, and files.
  • Modification (Tampering): Attackers intercept and change data before forwarding it to the destination. This is a threat to integrity. Examples include man-in-the-middle modification where attackers change transaction amounts or alter messages.
  • Interruption (Denial of Service): Attackers make network services unavailable to legitimate users. This is a threat to availability. Examples include DDoS attacks that flood networks with traffic and jamming attacks that interfere with wireless signals.
  • Fabrication (Impersonation): Attackers create fake network traffic or impersonate legitimate users or systems. This is a threat to authentication and integrity. Examples include IP spoofing, ARP spoofing, and DNS spoofing.

Specific Network Communication Threats

  • Packet Sniffing: Capturing network traffic to analyze it. Attackers use packet sniffers to steal unencrypted data such as passwords, emails, and files.
  • Man in the Middle Attack (MITM): The attacker positions themselves between two communicating parties, intercepting and potentially modifying messages. Both parties believe they are communicating directly.
  • Session Hijacking: Taking over a user's authenticated session by stealing session cookies or tokens. The attacker impersonates the user without needing the password.
  • Replay Attack: Capturing valid network traffic and retransmitting it later to trick the system. For example, an attacker might capture a valid login message and replay it to log in without the password.
  • DNS Spoofing (Cache Poisoning): Corrupting the DNS resolver cache so that legitimate domains (like bank.com) resolve to the attacker's malicious IP address instead.
  • ARP Spoofing (Poisoning): Attacker sends fake ARP messages linking their MAC address to the IP address of the gateway. All traffic intended for the gateway goes to the attacker instead — enabling MITM.
  • Evil Twin Wi-Fi Attack: Setting up a fake Wi-Fi access point with a legitimate-sounding name. Users connect, and the attacker captures all their traffic.

Question 5 · Part C

Illustrate various network security attacks.

5 Marks
Network security attacks are deliberate actions taken by attackers to compromise the confidentiality, integrity, or availability of network resources. Understanding these attacks is essential for designing effective defenses.

Various Network Security Attacks

  • Denial of Service (DoS) and Distributed Denial of Service (DDoS) Attacks: These attacks overwhelm network resources with excessive traffic, making services unavailable. In a DDoS attack, traffic comes from many sources simultaneously (a botnet), making it harder to block.
  • Man in the Middle (MITM) Attacks: The attacker secretly intercepts communication between two parties. The attacker can eavesdrop (read messages), modify (change messages), or inject (add fake messages).
  • Packet Sniffing (Eavesdropping): Attackers capture network traffic using packet sniffing tools. On shared networks, attackers can see all traffic. Used to steal passwords, emails, files, and other sensitive information transmitted without encryption.
  • IP Spoofing: Attackers create IP packets with a fake source address. This hides the attacker's true identity and can bypass firewall rules that trust traffic from specific IP addresses.
  • ARP Spoofing (ARP Poisoning): Attackers send fake ARP messages to associate their MAC address with a legitimate IP address. This allows the attacker to intercept traffic intended for that IP address.
  • DNS Spoofing (DNS Cache Poisoning): Attackers corrupt the DNS cache of a DNS server, causing domain names to resolve to the attacker's IP address. Users are redirected to fake websites controlled by the attacker.
  • Session Hijacking: Attackers steal a user's session token or cookie after the user has authenticated. The attacker can then impersonate the user without needing the password.
  • Replay Attacks: Attackers capture valid network traffic and retransmit it later. For example, capturing a valid login message and replaying it to gain access without knowing the password.
  • Port Scanning: Attackers scan a target's network ports to discover which services are running and which ports are open. Port scanning is reconnaissance, not an attack itself, but it helps attackers identify vulnerabilities.
  • Routing Attacks (BGP Hijacking): Attackers manipulate Border Gateway Protocol (BGP) routing tables to redirect internet traffic to their own networks, allowing them to intercept, monitor, or block traffic.
Multiple Attacks Used Together

A sophisticated attacker uses multiple network attacks in sequence:

  1. Port scanning identifies that a web server is running an outdated version with a known vulnerability.
  2. The attacker exploits the vulnerability to gain initial access.
  3. ARP spoofing is used to perform a man-in-the-middle attack, capturing traffic between the web server and the database server.
  4. The attacker steals database credentials from captured traffic.
  5. Using those credentials, the attacker accesses the database and steals customer data.
  6. The attacker uses IP spoofing to hide the source of the database queries.

Question 5 · Part D

Demonstrate various safety measures to ensure operating system security in network.

5 Marks
Operating System (OS) security in a network environment requires measures that protect the OS from both local and network-based threats. A secure operating system is the foundation of a secure network.

Safety Measures for Operating System Security in Network

  • Keep the Operating System Updated (Patch Management): Regularly apply security patches released by the OS vendor. Patches fix known vulnerabilities that attackers exploit. Critical patches should be applied within seven days. Unpatched operating systems are one of the most common targets for network attacks.
  • Use Host Based Firewall: Enable the built-in firewall on every OS. The firewall blocks unauthorized network traffic. Configure the firewall to block all incoming connections by default, allowing only necessary services.
  • Disable Unnecessary Services: Every running service is a potential entry point for attackers. Disable any services that are not needed. Reducing the attack surface makes the system harder to compromise.
  • Implement Strong Authentication: Require strong passwords (minimum twelve characters with complexity) for all user accounts. Implement multi-factor authentication for remote access and for administrator accounts. Use account lockout policies to prevent brute force attacks.
  • Use Principle of Least Privilege: Give users only the permissions they need to do their jobs. Regular users should not have administrator access. Even administrators should use separate accounts for administrative tasks.
  • Enable Audit Logging: Configure the OS to log security events including logins, logouts, failed login attempts, privilege escalations, and changes to security settings. Send logs to a centralized SIEM system for analysis.
  • Install and Maintain Antivirus / EDR: Install reputable endpoint protection with real-time scanning, scheduled scans, and automatic updates. Modern EDR also includes anti-malware, anti-ransomware, and anti-rootkit capabilities.
  • Configure Secure Remote Access: If users need remote access, require a Virtual Private Network (VPN) connection. Do not expose Remote Desktop Protocol (RDP) or other remote management interfaces directly to the internet.
  • Application Whitelisting: Create a list of approved applications that are allowed to run. Any application not on the list is blocked. This prevents users from installing unauthorized software and blocks malware that tries to execute.
  • Regular Security Scanning: Run vulnerability scanners against operating systems regularly to identify missing patches, weak configurations, and insecure settings. Address identified vulnerabilities promptly.
Example — Securing a Windows Server in a Network

A company secures its Windows server as follows:

  • Windows Update is configured to install security patches automatically within seven days.
  • Windows Firewall is enabled and configured to block all incoming traffic except web traffic (port 443) and remote management from the management subnet.
  • All unnecessary services such as print sharing and remote registry are disabled.
  • Multi-factor authentication is required for all administrator logins.
  • Regular users cannot log into the server at all.
  • Audit logging captures all login attempts and administrative actions, and logs are sent to the SIEM.
  • Microsoft Defender Antivirus is enabled with real-time protection.
  • Remote management is only allowed through a VPN, not directly from the internet.
  • Weekly vulnerability scans identify any missing patches or misconfigurations.
