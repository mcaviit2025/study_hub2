Topic 4.1

Inferential Statistics: Hypothesis Testing, Confidence Intervals, Chi-square Test, t-test, ANOVA

Inferential Statistics is the branch of statistics that allows researchers to draw conclusions about a population based on data collected from a sample. It includes hypothesis testing, confidence intervals, and various statistical tests to determine whether observed patterns are likely to reflect true population characteristics.
📌 Last Night Tip
Descriptive Statistics = describe your data (mean, median, SD). Inferential Statistics = draw conclusions about population from sample. Hypothesis testing asks: "Is this effect real or due to chance?"
Fig 4.1 — Descriptive vs Inferential Statistics

Hypothesis Testing

Hypothesis Testing is a statistical method for making decisions about population parameters based on sample data. It involves formulating competing hypotheses (null and alternative) and using sample evidence to decide which is more plausible.
Fig 4.2 — Hypothesis Testing Framework

Null and Alternative Hypotheses

❌ Null Hypothesis (H₀)

Definition: A statement of no effect, no difference, or no relationship. It represents the status quo that the researcher aims to test against.

Examples:

  • H₀: μ = 50 (population mean equals 50)
  • H₀: μ₁ - μ₂ = 0 (no difference between groups)
  • H₀: r = 0 (no correlation between variables)
  • H₀: There is no relationship between code review frequency and defect density

Key point: We never "accept" H₀ — we either "reject" or "fail to reject" it.

✓ Alternative Hypothesis (H₁ or Hₐ)

Definition: A statement that contradicts the null hypothesis. It represents what the researcher wants to support.

Types of Alternative Hypotheses:

  • Two-tailed (≠): H₁: μ ≠ 50 (difference in either direction)
  • One-tailed (greater): H₁: μ > 50 (difference in positive direction)
  • One-tailed (less): H₁: μ < 50 (difference in negative direction)

Example: H₁: There is a significant relationship between code review frequency and defect density.

Significance Level (α) and p-value

α

Significance Level (α)

Probability of rejecting H₀ when it is actually true (Type I Error).

Common values:

  • α = 0.05 (5% risk) — Most common
  • α = 0.01 (1% risk) — More stringent
  • α = 0.10 (10% risk) — Less stringent

Interpretation: α = 0.05 means 5% chance of concluding an effect exists when it doesn't.

p

p-value

Probability of obtaining results as extreme as observed, assuming H₀ is true.

Decision Rule:

  • If p < α → Reject H₀ (statistically significant)
  • If p ≥ α → Fail to reject H₀ (not significant)

Example: p = 0.03, α = 0.05 → Reject H₀ (significant)

⚠️

Type I & Type II Errors

Type I Error (α): Reject H₀ when it is actually true (false positive).

Type II Error (β): Fail to reject H₀ when it is actually false (false negative).

Power = 1 - β: Probability of correctly rejecting false H₀.

Confidence Intervals

Confidence Interval (CI) is a range of values that is likely to contain the population parameter with a certain level of confidence. It provides an estimate of precision and uncertainty around a sample statistic.
Fig 4.3 — Confidence Interval Interpretation
📐 Confidence Interval Formula (for means)
CI = x̄ ± Z × (σ / √n) OR CI = x̄ ± t × (s / √n)
Where: x̄ = sample mean, Z = Z-score (1.96 for 95%), t = t-value, s = sample SD, n = sample size
Confidence Interval Example

Research: Estimating average daily commits in software teams

Sample data: n = 100 teams, mean (x̄) = 12 commits, SD (s) = 5 commits

95% Confidence Interval:

  • Standard Error (SE) = s / √n = 5 / 10 = 0.5
  • Margin of Error (MOE) = 1.96 × 0.5 = 0.98 ≈ 1.0
  • CI = 12 ± 1.0 = (11.0, 13.0)

Interpretation: We are 95% confident that the true population mean daily commits is between 11.0 and 13.0 commits.

Compare to hypothesis test: If hypothesized value (e.g., 10) is outside CI, reject H₀ at α = 0.05.

Chi-square Test (χ²)

Chi-square Test is a non-parametric test used to determine whether there is a significant association between two categorical variables. It compares observed frequencies with expected frequencies under the assumption of independence.
Fig 4.4 — Chi-square Test Contingency Table
📐 Chi-square Formula
χ² = Σ [(O - E)² / E]
Where: O = Observed frequency, E = Expected frequency (under null hypothesis)
Degrees of freedom (df) = (rows - 1) × (columns - 1)
Chi-square Test Example — Agile Adoption by Company Type

Research Question: Is there an association between company type (Product vs Service) and adoption of agile methodology?

Observed Frequencies (O):

  • Product Company + Agile: 120
  • Product Company + Non-Agile: 60
  • Service Company + Agile: 80
  • Service Company + Non-Agile: 140

Step 1 — Calculate Expected Frequencies (E) under H₀ (independence):

E = (Row Total × Column Total) / Grand Total

  • E(Product-Agile) = (200 × 180) / 400 = 90
  • E(Product-NonAgile) = (200 × 220) / 400 = 110
  • E(Service-Agile) = (200 × 180) / 400 = 90
  • E(Service-NonAgile) = (200 × 220) / 400 = 110

Step 2 — Calculate χ²:

χ² = (120-90)²/90 + (60-110)²/110 + (80-90)²/90 + (140-110)²/110

= 900/90 + 2500/110 + 100/90 + 900/110

= 10 + 22.73 + 1.11 + 8.18 = 42.02

Step 3 — Compare to critical value: df = 1, critical value at α=0.05 = 3.84

Conclusion: 42.02 > 3.84 → Reject H₀. There is a significant association between company type and agile adoption (p < 0.001). Product companies are more likely to use agile.

t-test

t-test is a parametric test used to compare means between two groups. It determines whether the difference between group means is statistically significant.
1️⃣

One-Sample t-test

Compares sample mean to a known or hypothesized population mean.

Formula: t = (x̄ - μ) / (s/√n)

Example: Is the average defect density of your team (x̄=2.5) different from industry average (μ=3.0)?

H₀: μ = 3.0 | H₁: μ ≠ 3.0

2️⃣

Independent t-test

Compares means between two independent groups (different participants).

Example: Compare defect density between teams using agile (n₁=20) vs waterfall (n₂=20).

H₀: μ₁ = μ₂ | H₁: μ₁ ≠ μ₂

Assumptions: Normality, homogeneity of variance, independence

🔄

Paired t-test

Compares means between two related groups (same participants measured twice).

Example: Compare developer productivity before vs after implementing a new tool.

H₀: μ_difference = 0 | H₁: μ_difference ≠ 0

Formula: t = d̄ / (sd/√n) where d̄ = mean of differences

Independent t-test Example — Code Review Effectiveness

Research Question: Do teams with mandatory code review have lower defect density than teams without?

Data:

  • Review Group (n=15): Mean defects/KLOC = 2.5, SD = 0.8
  • No Review Group (n=15): Mean defects/KLOC = 3.8, SD = 1.0

Step 1 — Calculate t-statistic:

t = (x̄₁ - x̄₂) / √(s₁²/n₁ + s₂²/n₂) = (2.5 - 3.8) / √(0.64/15 + 1.0/15) = (-1.3) / √(0.0427 + 0.0667) = -1.3 / √0.1094 = -1.3 / 0.331 = -3.93

Step 2 — Degrees of freedom: df ≈ 28 (Welch approximation)

Step 3 — Critical value: At α=0.05, two-tailed, critical t = ±2.048

Conclusion: |t| = 3.93 > 2.048 → Reject H₀. Teams with code review have significantly lower defect density (p < 0.01).

Direction: One-tailed test would also be significant (t = -3.93 < -1.701).

Paired t-test Example — Training Effectiveness

Research Question: Does a 2-day agile training program improve team velocity?

Data (10 teams, velocity in story points per sprint):

TeamBeforeAfterDifference

Mean28.831.3+2.5

Calculate: mean difference (d̄) = 2.5, SD of differences = 2.8, n = 10

t = d̄ / (sd/√n) = 2.5 / (2.8/3.16) = 2.5 / 0.886 = 2.82

df = 9, critical t (α=0.05, two-tailed) = 2.262

Conclusion: 2.82 > 2.262 → Reject H₀. Training significantly improved team velocity (p < 0.05).

Analysis of Variance (ANOVA)

Analysis of Variance (ANOVA) is a statistical test used to compare means among three or more groups. It extends the t-test (which compares only two groups) to multiple groups while controlling Type I error.
Fig 4.5 — One-way ANOVA Concept
📐 ANOVA F-statistic
F = Variance Between Groups / Variance Within Groups = MS_between / MS_within
If F is large (p < α) → Reject H₀ → at least one group mean differs
One-way ANOVA Example — Testing Methodology Effectiveness

Research Question: Does the testing methodology (Manual, Automated, Hybrid) affect defect detection rate?

Data (defect detection rate %):

GroupnMeanSD
Manual2065.2%8.5
Automated2078.4%7.2
Hybrid2085.1%6.8

ANOVA Results:

  • F(2, 57) = 24.36
  • p < 0.001

Conclusion: Reject H₀. There is a significant difference in defect detection rate among the three testing methodologies.

Post-hoc Test (Tukey HSD): To find which groups differ:

  • Automated > Manual (p < 0.01)
  • Hybrid > Manual (p < 0.001)
  • Hybrid vs Automated: Not significant (p = 0.12)

Topic 4.2

Qualitative Data Analysis: Coding and Categorizing Data

Qualitative Data Analysis (QDA) is the process of examining, organizing, and interpreting non-numerical data (text, images, audio, video) to discover patterns, themes, and meanings. Coding is the central process in QDA — assigning labels to segments of data to identify and organize patterns.
📌 Last Night Tip
Qualitative analysis is NOT "less rigorous" than quantitative — it uses different standards. The core process: Raw Data → Coding → Categories → Themes → Interpretation. Trustworthiness comes from systematic, transparent methods.
Fig 4.6 — Qualitative Data Analysis Process

Coding in Qualitative Research

Coding is the process of assigning labels (codes) to segments of qualitative data to identify and organize patterns. Codes are the building blocks of qualitative analysis — they represent key ideas, concepts, or themes found in the data.

Types of Coding

🔤

Open Coding

Definition: Initial, exploratory coding where data is examined line-by-line to identify concepts and patterns without preconceived categories.

Process:

  • Read through data carefully
  • Identify meaningful segments
  • Assign descriptive labels
  • Generate many codes initially

Example code: "work-life balance," "communication challenges," "tool frustration"

📂

Axial Coding

Definition: A second-level coding that organizes open codes into categories and explores relationships between categories.

Process:

  • Group similar open codes
  • Identify category properties and dimensions
  • Explore cause-effect relationships
  • Connect categories to subcategories

Example: Group "tool frustration" + "slow response" + "frequent bugs" under "Technology Challenges"

⭐

Selective Coding

Definition: The final coding stage that identifies a core category or central theme that integrates all other categories.

Process:

  • Identify the main theme
  • Relate all categories to the core theme
  • Refine and validate relationships
  • Develop theoretical narrative

Example: Core theme = "Adaptation to remote work requires systematic support from leadership"

Fig 4.7 — From Codes to Themes: A Practical Example

Coding Approaches: Inductive vs Deductive

🔍 Inductive Coding (Bottom-up)

Definition: Codes and themes emerge from the data itself, without predetermined categories. The researcher lets the data "speak" for itself.

Process:

  • Read data with open mind
  • Generate codes based on what appears interesting
  • Group codes into emergent categories
  • Develop themes from categories

When to use:

  • Exploratory research
  • Little known about the topic
  • Want to discover unexpected patterns
  • Grounded theory methodology

Example: Analyzing interview transcripts about remote work — discovering "isolation" as an unexpected theme not in original research questions.

📋 Deductive Coding (Top-down)

Definition: Codes are predetermined based on existing theory, research questions, or conceptual framework. The researcher tests whether these expected patterns appear in the data.

Process:

  • Develop coding framework from literature
  • Apply predetermined codes to data
  • Look for evidence supporting/contradicting expectations
  • Quantify code frequencies

When to use:

  • Confirmatory research
  • Testing existing theory
  • Content analysis
  • Mixed methods research (to quantify themes)

Example: Coding job satisfaction interviews using Herzberg's motivation-hygiene theory — looking for predetermined categories like "recognition," "salary," "work conditions."

Practical Coding Process — Step by Step

Step-by-Step Coding Example — Remote Work Challenges Study

Data Source: Interviews with 15 software developers about remote work challenges

Step 1 — Prepare Data: Transcribe audio interviews, anonymize participant names.

Step 2 — Initial (Open) Coding: Read first 3 transcripts, label meaningful segments:

Transcript Excerpt                                 Code
"I find it hard to disconnect after work"         work-life boundary
"We use Slack but sometimes messages get lost"    communication tool issues
"My internet connection is unstable"              technical infrastructure
"I miss chatting with colleagues at lunch"        social isolation
"My manager expects immediate responses at 9pm"   unrealistic expectations
"Video calls are exhausting back-to-back"         meeting fatigue
"It takes longer to get answers than in office"   delayed responses
"I have more focus time without interruptions"    productivity benefit

Step 3 — Develop Categories (Axial Coding): Group similar codes together:

  • Work-Life Boundary Challenges: work-life boundary, unrealistic expectations
  • Communication Barriers: communication tool issues, delayed responses, meeting fatigue
  • Social/Economic Challenges: social isolation
  • Technical Infrastructure: technical infrastructure
  • Benefits of Remote Work: productivity benefit

Step 4 — Identify Themes (Selective Coding): Integrate categories into overarching themes:

  • Theme 1: Coordination Overhead — Communication barriers + Meeting fatigue + Delayed responses
  • Theme 2: Well-being Impacts — Work-life boundary + Social isolation + Unrealistic expectations
  • Theme 3: Environmental Factors — Technical infrastructure
  • Theme 4: Productivity Paradox — Productivity benefit + Distractions

Step 5 — Interpret and Write: Develop narrative explaining how these themes answer the research question.

Ensuring Trustworthiness in Qualitative Analysis

✓ Trustworthiness Criteria

Credibility (internal validity):

  • Prolonged engagement in the field
  • Triangulation (multiple data sources/methods/researchers)
  • Member checking (participants review findings)
  • Peer debriefing

Transferability (external validity):

  • Thick description (rich context for readers)
  • Purposive sampling for variation
  • Audit trail of decisions

✓ Trustworthiness Criteria (cont.)

Dependability (reliability):

  • Code-recode reliability
  • Intercoder reliability (kappa for multiple coders)
  • Stepwise replication
  • Audit trail documentation

Confirmability (objectivity):

  • Reflexivity journal (researcher self-awareness)
  • Practice bracketing (setting aside preconceptions)
  • Chain of evidence linking data to conclusions
Intercoder Reliability — Example

Scenario: Two researchers independently code the same 10 interview transcripts.

Agreement calculation:

SegmentResearcher A CodeResearcher B CodeAgreement
1CommunicationCommunication✓
2Work-lifeWork-life✓
3IsolationSocial✗
4ProductivityProductivity✓
5Tool issuesTechnology✗

Agreement rate: 3/5 = 60%

Action: Review disagreements, refine code definitions, recode until achieving 80%+ agreement.

Cohen's Kappa: Statistical measure that accounts for chance agreement — target κ > 0.70.

Unit 4 — Key Takeaway

Data analysis transforms raw data into meaningful insights. Inferential statistics allows researchers to draw conclusions about populations from samples through hypothesis testing, confidence intervals, and tests like t-test, chi-square, and ANOVA. Qualitative analysis uses coding and categorizing to identify patterns and themes in textual data. Both approaches require systematic rigor — quantitative demands statistical assumptions and power, qualitative demands transparency and trustworthiness. The choice of analysis method must align with research questions, data type, and research design.
